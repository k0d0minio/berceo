## Definition of done

- [ ] `/inscription-famille` shows the guide's message and hook sentence, the six fields with the guide's labels, the e-mail helper line verbatim, the phone helper line without any SMS claim, one required consent checkbox linking `/conditions-generales` and `/confidentialite`, and the button "Créer mon compte".
- [ ] A family that submits a valid form sees "Votre compte est créé. Vérifiez votre boîte e-mail pour activer votre accès." and receives a verification e-mail in Berceo's layout (logotype, "Bonjour [Prénom],", "L'équipe Berceo"), sent from the address in `EMAIL_FROM`.
- [ ] Submitting with an address that already has an account shows the same message and reveals nothing.
- [ ] Invalid input (empty field, malformed e-mail or phone, password under 8 characters, mismatched confirmation, unticked consent) is refused with a French message on the field concerned, and no account is created.
- [ ] Following the verification link verifies the address, signs the user in and lands them in their space. A family receives the welcome e-mail with the guide's subject and body exactly once, even if the link is opened twice.
- [ ] An unverified account cannot reach a space. Signing in with it shows a message and lets the user resend the verification link.
- [ ] Signing in with a wrong e-mail or password shows "L'adresse e-mail ou le mot de passe est incorrect. Vérifiez vos informations et réessayez." whichever one was wrong.
- [ ] "Mot de passe oublié ?" leads to a form whose confirmation is always "Si un compte existe avec cette adresse, vous recevrez un e-mail dans quelques minutes.". Only an existing account receives the reset e-mail. Its link sets a new password, and the old one no longer works.
- [ ] Signing out through the confirmation dialog ends the session and returns to `/connexion`. Afterwards `/espace/famille` redirects to `/connexion`, and after signing in the user lands back where they were going.
- [ ] A professional who signs up at `/inscription-professionnelle` and verifies her e-mail lands in `/espace/professionnelle`, which shows "Votre compte est en attente de validation. Nous vous contacterons dès que votre profil sera activé." She can sign out and back in, and sees it again.
- [ ] Every account created through a sign-up form has, in the database, one `users` row with its role, `auth_user_id`, first name, last name and E.164 phone, and two `user_consents` rows (`cgu`, `confidentialite`), each with the current version and an `accepted_at` timestamp.
- [ ] Each role lands in its own space after sign-in. A parent opening `/espace/professionnelle` is redirected to `/espace/famille`. A parent or a professional opening `/admin` gets a 404.
- [ ] `npm run admin:grant -- --email <address>` turns an existing account into an admin, who then lands in `/admin`. The script refuses an unknown address, and no address is committed.
- [ ] `/api/webhooks/neon-auth` answers 401 to an unsigned, wrongly signed or stale request and sends nothing. Delivering the same event id twice sends one e-mail. Tests cover these cases.
- [ ] Neon Auth no longer sends its own e-mails, and Google sign-in is not offered on `main` or `preview/uat`.
- [ ] The migration is generated by drizzle-kit, the journal test passes, and a preview and uat.berceo.be build apply `0000` and the new migration to their own Neon branch through `vercel-build`, with `db:verify` passing.
- [ ] Every visible word of the auth pages, the spaces and the e-mails lives in `src/content/`, and each entry not verbatim from the guide carries `@relecture Surya`. No page or e-mail uses an exclamation mark, an em dash, an ellipsis, or the words "assurance Berceo".
