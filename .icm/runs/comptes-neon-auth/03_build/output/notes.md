## Two things the SDK does not do, found by probing the live endpoint

- `auth.verifyEmail()` POSTs; Neon's `verify-email` answers 404 to POST and 401
  `INVALID_TOKEN` to GET. So the e-mail link goes to our `/verification-email/confirmer`, which
  forwards the token through the SDK's own `/api/auth` proxy handler (GET): the session cookie
  lands on this origin and the user arrives signed in.
- The SDK middleware drops the return path; `src/proxy.ts` wraps it and adds `?retour=`.
