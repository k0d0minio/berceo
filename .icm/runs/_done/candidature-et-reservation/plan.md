# Plan: candidature-et-reservation

Build's execution plan in passes — each pass one layer of the change, in the order it lands, so
a session that resumes mid-build sees where it is. Written by the advisor pass (Define, or
Build's first act on `sonnet` after reading the spec), executed pass by pass, and rewritten when
reality disagrees with it — never left describing a plan that was abandoned.

2. **The rules module** — `src/lib/reservations/rules.ts` (pure): who may answer (each refusal of §1), the same-night rule, the accept transition (request → `attribuee`, chosen → `retenue`, others → `non_retenue`, her same-night answers → `retiree`), the republish transition, the cancel transition's effect on answers, the edit lock with pending answers (wired into `src/lib/demandes/rules.ts`' `isChangeable`), who may read a photo (`canReadFile` in `src/lib/professionnelle/rules.ts` gains the parent-reads-a-`valide`-photo case), the récapitulatif's hours and duration — done when: unit tests cover each rule and each refusal.

## Risks

- **The address or the family's identity leaking to a professional before confirmation.** Signal: any professional-facing query selecting `users.first_name`/`last_name`/`phone`/`email` or a `family_profiles` address column outside `src/lib/famille/`'s booking reader. Guard: the column tests and the existing address guard test.
- **Two acceptances racing, or a professional double-booked on a night.** Signal: two `bookings` rows for one request or one professional-night. Guard: the conditional UPDATE on the request and the two unique indexes; a test runs two accepts.
- **The enum value `attribuee` and its first use in one migration.** Postgres refuses to use a value added by `ALTER TYPE … ADD VALUE` in the same transaction; the migration must not reference `'attribuee'` in a check or index it creates. Signal: `db:verify` red on the preview branch.
- **The digest's « already sent today » check reading a republished request.** `digestSentOn(day)` keys on `digest_sent_at`; clearing it on republish must not let a second digest leave the same day or swallow the re-announced request. Signal: the digest route test.
- **Stub 9 (frais-de-service) inserts payment between the click and the booking.** Keep the accept path one function in `src/lib/reservations/` so it can become « pending until the webhook » without touching the pages.
